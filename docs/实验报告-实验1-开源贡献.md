## 三、实验内容与步骤

### 3.1 准备 GitHub 与仓库

1. 注册/登录 GitHub 账号：**Mut5uki**。
2. 创建公开仓库 [python-voice-assistant](https://github.com/Mut5uki/python-voice-assistant)，用于课程设计「语音学习助手」。
3. 本地克隆或关联远程：

```bash
cd VoiceAssistant
git remote add origin https://github.com/Mut5uki/python-voice-assistant.git
```

### 3.2 推送项目初始代码

将课设已实现的 AI+音频模块推送至 `main` 分支，包括：

- `ai/`：录音、Whisper 识别、文本处理、TTS、`pipeline` 编排
- `run_demo.py` / `run_demo.bat`：命令行演示入口
- `requirements-ai.txt`、`README.md`

推送命令示例：

```bash
git add .
git commit -m "chore: initial import of voice assistant AI module"
git pull origin main --allow-unrelated-histories
git push -u origin main
```

### 3.3 创建 Issue

在仓库 **Issues** 页新建 Issue，标题：

> `feat: 添加 CLI 命令列出系统录音设备`

描述见仓库内 `docs/issue-001-list-audio-devices.md`。

**Issue 动机：** 用户反馈/自测时发现无法确认当前使用的麦克风（系统默认输入设备不明确），需增强可观测性。

### 3.4 使用 AI 完成开发

在 Cursor 中向 AI 说明 Issue 需求，由 AI 辅助：

1. 查阅 `sounddevice.query_devices()` API；
2. 在 `audio_io.py` 实现 `list_input_devices()`；
3. 在 `demo_cli.py` 注册 `devices` 子命令；
4. 更新 `README.md`。

**人工参与：** 核对设备列表输出是否符合本机「录音」控制面板中的设备；运行 `python run_demo.py devices` 验证。

### 3.5 提交 Pull Request

```bash
git checkout -b feature/list-audio-devices
# ... 完成开发 ...
git add ai/audio_io.py ai/demo_cli.py README.md
git commit -m "feat(cli): add devices command to list input audio devices"
git push -u origin feature/list-audio-devices
```

在 GitHub 打开 **Compare & pull request**，关联 `Closes #1`，填写说明（见 `docs/pull-request-001.md`），合并至 `main`。

## 四、核心改动说明

### 4.1 新增 API（`ai/audio_io.py`）

- `list_input_devices()`：枚举 `max_input_channels > 0` 的设备，返回结构化列表。
- `format_devices_text()`：格式化打印，并标注系统默认输入设备 index。

### 4.2 CLI（`ai/demo_cli.py`）

```bash
python run_demo.py devices
```

### 4.3 设计说明

录音模块使用系统**默认输入设备**，不绑定硬件型号。列出设备便于课设演示与排错（如无物理麦克风时的静音检测问题）。

## 七、问题与收获

**问题：** 开发机无物理麦克风时，录音为静音；已通过 RMS 静音检测与 `session --text` 文字模式解决。

**收获：**

1. 掌握 Issue → 分支 → PR → Merge 的协作流程；
2. 理解开源贡献不限于第三方大型项目，自有课设仓库也可规范演练；
3. AI 适合完成样板代码与文档，关键逻辑与运行结果需人工验证。
